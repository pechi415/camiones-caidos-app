## 6. Arquitectura de Autenticación y Seguridad

### 6.1 Relación `auth.users` ↔ `public.app_users`
- **Mecanismo:** La autenticación se desacopla completamente de la tabla de aplicación. `auth.users` (GoTrue) administra credenciales, contraseñas hash (bcrypt/argon2) y emisión de JWT.
- **Enlace:** `public.app_users.auth_user_id` contiene el UUID unívoco de `auth.users.id`.
- **Email Técnico Canónico:** Dado que el personal de campo se identifica mediante su número de cédula, el sistema deriva un correo electrónico técnico determinista:
  $$\text{email} = \text{cédula} + \text{"@camionescaidos.internal"}$$
- **Flujo de Inicio de Sesión (`signInWithPassword`):**
  1. El usuario ingresa su cédula y contraseña en el `LoginForm`.
  2. `AuthContext` normaliza la cédula y genera el correo técnico.
  3. Invoca `supabase.auth.signInWithPassword({ email: technicalEmail, password })`.
  4. Recibe la sesión y extrae `auth_user_id`.
  5. Consulta `public.app_users` filtrando por `auth_user_id = user.id` para cargar perfil, rol y sede.
  6. Si `must_change_password === true`, activa el modal bloqueante `PasswordChangeModal`.

### 6.2 Sesión, Refresco y Resiliencia Offline
- **Persistencia de Sesión:** Manejada por `@supabase/supabase-js` utilizando `localStorage`.
- **Perfil en Caché:** Al validar el perfil en línea, se guarda una copia en `localStorage['camiones_user_profile']`.
- **Modo Offline:** Si el usuario recarga la página sin conectividad (o se encuentra en una zona ciega de la mina), `fetchProfileByAuthId` detecta el fallo de red (`navigator.onLine === false` o error de transporte) y restaura el perfil desde la caché local sin cerrar la sesión ni enviar al usuario al login.
- **Reconexión:** Al dispararse el evento `window.addEventListener('online')`, `AuthContext` revalida silenciosamente el perfil en Supabase Cloud.

## 7. Modelo de Base de Datos y Políticas RLS

### 7.1 Esquema DDL de Tablas Principales

```sql
-- 1. Tabla de Usuarios (Perfiles de aplicación)
CREATE TABLE IF NOT EXISTS public.app_users (

-- 2. Tabla de Operadores (Censo de acarreo)
CREATE TABLE IF NOT EXISTS public.operators (
    id TEXT PRIMARY KEY,

-- 3. Tabla de Reportes de Camiones Caídos
CREATE TABLE IF NOT EXISTS public.truck_reports (
    id TEXT PRIMARY KEY,

    shift TEXT NOT NULL DEFAULT 'Diurno',

    system TEXT,

    actual_return_time TEXT,
```

### 7.2 Arquitectura Relacional Dual en `truck_reports`
La tabla `truck_reports` implementa un patrón de **doble captura intencional**:
1. `operator_id` (Clave Foránea lógica a `operators.id`): Permite relacionar eventos, analizar reincidencias de operadores y realizar cruces analíticos.
2. `operator` (Snapshot Textual): Preserva la cadena literal del operador al momento exacto en que ocurrió la falla.
- **Justificación Técnica:** Garantiza que si un operador es corregido, renombrado o dado de baja del censo, los reportes históricos mantengan inalterable su valor documental para auditorías mineras y reportes PDF/Excel, sin requerir joins costosos ni generar inconsistencias por borrado en cascada.

### 7.3 Políticas de Seguridad RLS (Row Level Security)
Row Level Security está habilitado en las tres tablas (`ALTER TABLE ... ENABLE ROW LEVEL SECURITY`). Se aplican 11 políticas activas:

| Tabla | Política | Operación | Roles Permitidos / Cláusula USING |
| :--- | :--- | :---: | :--- |
| `app_users` | `app_users_select_authenticated` | `SELECT` | `is_admin() OR (auth_user_id = auth.uid())` |
| `app_users` | `app_users_update_admin` | `UPDATE` | `is_admin()` |
| `app_users` | `app_users_update_self` | `UPDATE` | `auth_user_id = auth.uid()` |
| `operators` | `operators_select_authenticated` | `SELECT` | `true` (Todos los usuarios autenticados) |
| `operators` | `operators_insert_admin` | `INSERT` | `is_admin()` |
| `operators` | `operators_update_admin` | `UPDATE` | `is_admin()` |
| `operators` | `operators_delete_admin` | `DELETE` | `is_admin()` |
| `truck_reports` | `truck_reports_select_authenticated` | `SELECT` | `is_admin() OR (mine = get_auth_user_mine())` |
| `truck_reports` | `truck_reports_insert_authenticated` | `INSERT` | `is_admin() OR (mine = get_auth_user_mine())` |
| `truck_reports` | `truck_reports_update_authenticated` | `UPDATE` | `is_admin() OR (mine = get_auth_user_mine())` |
| `truck_reports` | `truck_reports_delete_authenticated` | `DELETE` | `is_admin() OR ((get_auth_user_role() = 'Encargado') AND (mine = get_auth_user_mine()))` |

*Nota Crítica de RLS:* En `app_users` **no existen políticas de INSERT ni DELETE para usuarios autenticados**. Las inserciones y eliminaciones se ejecutan exclusivamente desde Edge Functions con privilegios de `service_role`.

### 7.4 Trigger de Blindaje de Columnas (`trg_protect_app_users_columns`)
Función `SECURITY DEFINER` con `search_path = 'public'` asociada al trigger `BEFORE UPDATE ON public.app_users`:
- **Inmutabilidad Absoluta:** Prohíbe terminantemente la alteración de `id`, `national_id`, `auth_user_id` y `created_at` para todos los usuarios (incluso administradores y directos).
- **Bypass Exclusivo para Backend:** Se permite modificación técnica únicamente si `(auth.jwt() ->> 'role') = 'service_role'` o en sesión nativa de DBA (`session_user = 'postgres' AND auth.jwt() IS NULL`).
- **Restricciones para No Administradores:** Si el usuario no es Administrador, tiene terminantemente denegado modificar `role`, `mine`, `group_name` o `name`, y no puede revertir `must_change_password` de `false` a `true`.

## 8. Supabase Edge Functions (Serverless Deno)

Ubicadas en `supabase/functions/`, ejecutadas bajo Deno runtime con soporte CORS compartido (`_shared/cors.ts`):

### 8.1 `admin-create-user`
- **Propósito:** Creación atómica de una nueva cuenta de usuario.
- **Autenticación / Autorización:** Requiere cabecera `Authorization: Bearer <token>`; valida en `app_users` que el invocador tenga rol `'Administrador'`.
- **Entrada:** `{ name, nationalId, role, mine, group, avatar }`.
- **Contraseña Temporal Asignada:** `caidos1234`.
- **Protecciones:**
  - Valida duplicados en `app_users` y en `auth.users` (retorna `409 Conflict`).
  - Crea usuario en `auth.admin.createUser`.
  - Inserta en `public.app_users` con `must_change_password: true`.
  - **Mecanismo de Rollback Compensatorio:** Si la inserción en `app_users` falla, la función ejecuta de inmediato `auth.admin.deleteUser(authUserId)` para evitar la creación de usuarios huérfanos en Auth.

### 8.2 `admin-reset-password`
- **Propósito:** Restablecimiento administrativo de credenciales ante olvido o bloqueo.
- **Autenticación / Autorización:** Requiere token JWT con rol `'Administrador'`.
- **Entrada:** `{ target_app_user_id }`.
- **Contraseña Temporal Asignada:** `caidos1234`.
- **Mecanismo de Resiliencia:** Ejecuta `auth.admin.updateUserById(targetAuthUserId, { password: 'caidos1234' })` y luego actualiza `must_change_password = true` en `app_users` implementando hasta 3 reintentos con retroceso exponencial (*exponential backoff*).

### 8.3 `admin-delete-user`
- **Propósito:** Purga completa y coordinada de un usuario.
- **Autenticación / Autorización:** Requiere token JWT con rol `'Administrador'`.
- **Entrada:** `{ target_app_user_id }`.
- **Protecciones Críticas de Gobernanza:**
  1. *Protección contra Autoeliminación:* Valida `targetUser.auth_user_id === callerUser.id`; rechaza con HTTP `400 Bad Request`.
  2. *Protección del Último Administrador:* Realiza un recuento de administradores (`count <= 1`); si es el único, bloquea la operación para evitar dejar el sistema sin gobernanza.
  3. *Eliminación Coordinada:* Elimina la cuenta en `auth.admin.deleteUser` y posteriormente elimina el registro de `public.app_users`.

## 13. Guía de Resolución de Incidentes (Runbook Técnico)

| Incidente | Síntoma Principal | Diagnóstico | Acción Correctiva | Verificación |
| :--- | :--- | :--- | :--- | :--- |
| **Fallo de Carga de Frontend** | Pantalla en blanco con error `ChunkLoadError` o `Failed to fetch dynamically imported module`. | El navegador tiene un Service Worker desactualizado que solicita hashes antiguos ya purgados de Vercel. | Forzar la actualización del Service Worker mediante `skipWaiting()` o instruir al usuario a presionar `Ctrl + F5` (o limpiar almacenamiento del sitio). | La aplicación carga el nuevo `index-<hash>.js` y renderiza el Dashboard. |
| **Indisponibilidad de Supabase** | Notificaciones de *"Error al sincronizar con la base de datos"* en la consola; fallas en endpoints REST. | Caída del servicio en Supabase Cloud, problemas de DNS o límite de conexiones en el pooler de PostgreSQL. | Verificar estado del servicio en `status.supabase.com`. La aplicación conmuta automáticamente a modo lectura offline usando la caché local. Si persiste, reiniciar la instancia desde el panel de Supabase. | Restauración de peticiones HTTP 200 en las llamadas a `/rest/v1/truck_reports`. |
| **Bloqueo de Sesión / JWT Expirado** | Peticiones retornan HTTP 401 Unauthorized; la sesión se desconecta inesperadamente. | El token de refresco en `localStorage` caducó o el usuario fue desvinculado en `auth.users`. | `AuthContext` captura el error 401 y ejecuta `logout()` limpio. El usuario debe volver a ingresar sus credenciales en `LoginForm`. | Re-autenticación exitosa y emisión de un nuevo JWT válido. |
| **Inconsistencia de Datos / operator_id** | Un reporte aparece en la interfaz con operador en blanco o sin coincidencia. | Se eliminó un operador del censo sin considerar reportes que lo referenciaban, o se insertó un `operator_id` inválido. | El sistema utiliza el fallback de snapshot textual `report.operator`. Para asociarlo a un nuevo operador, el Administrador debe editar el reporte y volver a seleccionar al operador en el autocompletado. | El reporte muestra nuevamente el operador vinculado y persiste en la base de datos. |
| **Caché Local Corrupta en PWA** | La aplicación móvil no refleja cambios recientes aun con conexión activa. | Datos corruptos en `localStorage` (`camiones_reports`) o conflicto de versiones en IndexedDB. | Ejecutar la función interna de limpieza de caché o borrar almacenamiento desde la configuración del navegador móvil (*Borrar datos de navegación -> Almacenamiento del sitio*). | La aplicación descarga el censo completo de 814 operadores y los 347 reportes desde Supabase. |
| **Falla de Edge Function en Creación de Usuario** | Alerta *"Error en el servidor al procesar la solicitud"* (HTTP 500) en `UserManager`. | La función falló por credenciales de servicio desconfiguradas o error en Supabase Auth. | Inspeccionar los logs de la función en la consola de Supabase (*Edge Functions -> Logs*). Verificar que el rollback compensatorio haya eliminado la cuenta en Auth. **REQUIERE PROCEDIMIENTO ADICIONAL** si se generan usuarios huérfanos. | Reintento exitoso de creación con código HTTP 201. |

## 14. Inventario de Archivos Sensibles y Críticos (Protected Files)

Los siguientes módulos del repositorio han sido identificados como **componentes arquitectónicos de alta sensibilidad**, sobre los cuales no deben realizarse modificaciones no planificadas:

1. **`src/context/AuthContext.jsx`:**
   - *Razón Técnica:* Contiene la lógica integral de seguridad de la aplicación: gestión de tokens JWT, derivación de correo técnico, mitigación de fallos de red offline y orquestación con Edge Functions. Un error en este archivo puede bloquear el acceso a todos los usuarios del sistema.
2. **`src/context/ReportContext.jsx`:**
   - *Razón Técnica:* Centraliza el estado operacional de los 347 reportes y los 814 operadores, la sincronización en segundo plano con Supabase y la lógica de ordenamiento cronológico compuesto.
3. **`src/components/Layout/MobileNav.jsx`:**
   - *Razón Técnica:* Implementa el sistema de navegación móvil adaptativo con física táctil e interactividad gestual.
4. **`src/components/Layout/LiquidLensCanvas.jsx`:**
   - *Razón Técnica:* Renderiza animaciones físicas mediante Canvas 2D y recorte vectorial por GPU con cálculos de tensión superficial para la lente líquida móvil. Es propenso a roturas de rendimiento si se modifican sus buffers.
5. **`src/components/Forms/TruckReportModal.jsx`:**
   - *Razón Técnica:* Formulario maestro de captura de camiones caídos; gestiona el autocompletado contra 814 operadores, la captura simultánea de `operator_id` y `operator`, y la validación de horas y turnos mineros.
6. **`src/utils/pdfUtils.js`:**
   - *Razón Técnica:* Módulo crítico para la entrega de informes gerenciales a Drummond; contiene las definiciones de maquetación milimétrica, paginación e incrustación de logotipos corporativos en base64.
7. **`supabase/functions/admin-create-user/index.ts` y `admin-delete-user/index.ts`:**
   - *Razón Técnica:* Custodian las reglas de gobernanza institucional, validación de contraseñas temporales (`caidos1234`), mitigación de duplicados y protección del último administrador.
